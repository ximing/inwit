为什么需要交叉验证

交叉验证是评估模型泛化能力的标准做法。它将数据切成 k 份，轮流用其中一份做验证、其余做训练，最后取 k 次结果的平均。

相比单次划分，它的好处是评估结果对「恰好分到好验证集」这件事不敏感，方差更小。实际中最常用的是 k = 5 或 k = 10。

  • 胶囊弱视觉：默认无底色、无边框、无阴影，只是一排小字和小图标；hover 时才浮现胶囊底。常驻画面里几乎感觉不到它。
  • 同一排：主题 kicker 在左、工具丸在右，一行收掉原来两层；题区顶部留白 48px → 24px。
  • 标题：衬线 30px，与 sans 正文形成字体对比；meta 一道 hairline 收尾，题区与正文分界明确。
  • 阅读态可把胶囊设为「滚动向下时淡出、hover 或向上滚动浮现」，进一步零干扰。

为什么需要交叉验证

交叉验证是评估模型泛化能力的标准做法。它将数据切成 k 份，轮流用其中一份做验证、其余做训练，最后取 k 次结果的平均。

相比单次划分，它的好处是评估结果对「恰好分到好验证集」这件事不敏感，方差更小。

  • 「关闭」变成面包屑返回：‹ 文档 / 主题名，一行同时完成导航、定位、关闭三件事，语义比裸 X 更清楚。
  • 无分隔线无背景：工具行完全融入页面，视觉上正文往上提了整整一截。
  • meta 用 pill：卡数、消化状态从文字分隔改成小胶囊，扫读更快。
  • 代价：面包屑需要承载主题切换（点击主题名弹 TopicPicker），交互要重新约定。
