# M0：任务原型与布局基线

依据：三个方案文档 v3。类型：**设计走查**，没有真实用户参与。M0 交互原型、六组任务路径和布局基线已交付；真实键盘及辅助技术验收仍待补，不宣称全面可用性验收。M1 未启动。

## 1. 交付及方法

入口：[可交互 HTML](../../design/prototypes/concept-relations.html)；[预览说明](../../design/prototypes/concept-relations-m0/README.md)。在仓库根目录启动 `python3 -m http.server 8765 --bind 127.0.0.1 --directory docs/design/prototypes`，打开 `http://127.0.0.1:8765/concept-relations.html`。

原型沿用暖纸底、墨色、朱批强调、衬线正文；拆分本地数据、CSS 和 JS。未安装依赖，未修改 apps/、packages/、数据库或生产协议，未部署、提交或推送 Git。

执行步骤：

- [x] 建立同一份 8 章、20 划线、15 卡、12 概念、18 关系的受控示例。
- [x] 完成 A/B、独立状态、显式定位/返回、卡片共用、关系编辑、候选确认、模拟复习。
- [x] Chrome 中运行两方案 × 三视口的五类任务、截图和几何检查。
- [x] 检查刷新草稿、独立相机、阅读恢复、失效来源及删除焦点；更新布局基线。
- [ ] 真实键盘、触屏和读屏器走查；见限制。

浏览器工具：CSI，真实 Chrome，CDP 视口为 CSS 像素、deviceScaleFactor=1。任务断言通过 DOM 点击/输入事件触发实际页面事件处理器，读取 DOM 和只读 `M0.snapshot()` 检查结果；不是人工用户计时实验。每组从同一初始数据重置，A/B 共用实体且各自保留操作状态。截图取任务完成后的工作区；B 展示 Trial 局部浮层。

[六组任务证据](../../design/prototypes/concept-relations-m0/evidence/task-results.json) 每组 20 项断言，均通过；[刷新与状态证据](../../design/prototypes/concept-relations-m0/evidence/state-results.json)；[滚动、候选及环证据](../../design/prototypes/concept-relations-m0/evidence/additional-state-results.json)。这些数量是程序断言数量，不是用户完成率。

没有收集真实完成时间、误选次数、用户重新缩放次数或对照停留时间，均记为“未测”，不以脚本步骤代替这些指标。五类脚本路径不需要 fit-all；跨章节任务按用户指令显式定位并返回，不能据此推断用户不需要反复缩放。

## 3. 五类任务路径

以下路径在 A/B 的三个视口均执行。窄屏需滚动到下方学习区；A 根据最近焦点显示一个图，B 在脑图区域内显示局部浮层。原始断言详见 JSON。

| 任务 | 可复现路径 | 观察与结果 |
| --- | --- | --- |
| 1. Trial 与 Task 的区别、依据 | 正文第 1 章选 Trial → 详情“Task → 可以进行多次 → Trial” → 阅读区别、例子和 h2 引文 → 定位原文依据 → 返回定位前状态 | 显示目标与一次执行的区别；来源定位和返回有效，普通选择未改变另一图相机 |
| 2. 三章出现位置 | Trial → 查看全部出现位置 → 分别选第 1/2/4 章 → 每次定位后返回 | 返回 3 个显式选择项；只在定位时展开对应章节、移动脑图；返回恢复展开和相机 |
| 3. 修改关系再回阅读 | r1 详情 → 修改关系 → 修改解释 → 保存 → 工作区 | 实际关系对象变更，阅读位置与两图相机不变；未保存关闭后可重入编辑，刷新保留草稿 |
| 4. 确认新生成内容 | 模拟 Agent 生成 → 查看候选 → 核对推断及来源 → 明确勾选关系 → 收录所选 | 12/18 变为 13/19；新增不 fit、不抢焦点，原有选择保持；“新收录”过滤可访问新增概念 |
| 5. 从关系复习并返回 | r1 → 模拟关系复习 → 输入回答 → 揭晓解释 → 选择反馈 → 返回工作区 | 揭晓前关系答案隐藏；揭晓及反馈改变本地复习状态，返回保留阅读与相机，不建立真实排期 |

## 5. 两方案比较与布局决定

推荐保留 **A 可聚焦双视图** 为首版方向，B 只用于本次比较，不纳入首版范围。

| 维度 | A | B | 设计走查判断 |
| --- | --- | --- | --- |
| 持续对照 | 章节高亮和关系保持同时可见 | 浮层会覆盖脑图关联卡和章节 | 跨章节/共享卡任务更适合 A；这是可见性依据，不是计时收益结论 |
| 就地读一个概念 | 需在概念区查详情 | 从正文或卡片直接打开局部解释 | B 的单次查询路径自然，但关闭浮层是继续看完整脑图的必要操作 |
| 编辑、候选及复习返回 | 原画布与详情有稳定归属 | 可以保留状态，但浮层/详情占据同一空间 | 两版都可完成；A 更适合持续维护 |
| 笔记本 | 上下排列给图约 935px 宽，概念图仅约 261px 高 | 浮层更高，覆盖更大 | A 初始局部六节点可读，深层脑图仍要定位/放大；不可宣称 260px 适合全图 |
| 宽屏 | 三栏约 629/619px 图宽，正文约 599px；初始六节点可读 | 原脑图很宽但打开浮层后被遮挡 | A 三栏可用，也保留上下排列选择 |
| 窄屏 | 正文和当前图上下，页面需滚动 | 浮层几乎覆盖脑图，空间优势消失 | 不做三栏；优先索引、详情和显式定位 |

采用的 **M0 设计基线**（受控样例的起点，不是人因阈值证明）：

1. 工作区可用宽度 ≥1650px，且高度 ≥420px：默认可横向三栏，用户可改上下排列。默认正文比例 32%，两图均分其余空间；保留用户调节值。
2. 可用宽度 ≥1280px、可用高度 ≥720px，但不足三栏条件：正文在左、右侧双图上下。分隔按图的可读面积限幅；本样例右侧保留约 780px 以上宽度，图画布不少于约 260px 高。1440×900 下实测为 935×278 和 935×261。
3. 不满足对照条件时降级为最近主动焦点的单图；preferred mode 与 effective mode 分离。恢复空间后恢复对照偏好，不能覆盖用户选择。
4. ≤760px 使用正文在上、当前学习区在下，独立滚动；390px 下正文面板 366px、图宽 364px。360px 正文面板可作为下限防线，但并未证明更窄正文的可读性。320×260px 只作为图的保护下限，**不是可默认三栏的充分条件**。
5. 详情在所属图内出现，可收起，不增加第四常驻栏。图的相机、展开、选择互相独立；默认联动只高亮。临时放大不覆盖原布局与比例，返回后恢复。
6. 仅“定位”改变另一视图路径/相机，并保存返回帧；多位置必须先选择。新增节点保留旧节点坐标和相机，不自动 fit；全局概念图允许合法环。

## 6. 发现的问题、修正与局限

已修正：工具栏挤占笔记本图高（合并概念工具栏）；章节固定行距导致展开卡片重叠（按展开内容计算行距）；B 的 100% 宽与绝对定位边距叠加导致页面溢出（改为按 inset 计算）；宽屏正文过宽使右侧节点被裁切（默认 32% 并收紧节点间距）；水平关系标签与节点争用位置（标签置于连线上方）；重绘后键盘节点焦点丢失（按动作/身份找回）；程序恢复滚动与用户滚动分开，避免布局切换覆盖已存滚动位置。

状态验证包括 A/B 相机独立、原文/两图不随生成重置、详情与列表滚动、刷新后阅读锚点及编辑草稿、候选取消依赖及草稿、窄屏退化与宽屏恢复、失效 h2 不跳转、删除当前概念关闭失效详情但保留相机。列表与概念详情的实际滚动恢复另有单独断言。关系、卡片、候选均是本标签模拟实体。

仍需补充：

- **真实键盘与辅助技术**：DOM KeyboardEvent 验证分隔线方向键和节点 Enter、焦点保持；CSI send_keys / CDP Input 命令未到达页面监听器，不能据此宣称真实键盘通过。真实 Tab 顺序、读屏器、触屏拖动未验证。
- 没有真实用户测试，无任务耗时、误操作、学习效果或缩放频率数据。正式布局应再做小规模任务测试，特别关注 260px 高画布是否导致过多移动。
- 三个指定视口已验证；其他断点边界、浏览器缩放、长文本/超长标签、多语言、不同系统字体和其他浏览器未穷举。阈值是设计选择，正式容器应测量工具栏占高及真实可用空间，不直接套屏幕型号。
- 概念全图仍有连线交叉和密集标签，局部阅读/详情/列表比全局缩小更可靠；未实现生产自动布图、分页、虚拟化、并发或权限。
- 候选即时生成，无真实任务进度、模型失败或后端恢复。模拟复习只保留回答、揭晓、反馈，不实现调度算法。
- sessionStorage 只承诺本标签刷新恢复；原型刷新后不自动重开模态框，需重入同一编辑或复习入口。没有跨用户、跨设备、跨标签业务同步验证。

M0 在此停止。上述局限不能转写成 M1 或后续生产任务已完成。
