# T2：数据层改造 — DTO + DB migration + server 文档存取链路 contentJson 化

先完整阅读 `docs/tasks/unified-doc-engine/PLAN.md`（设计定稿，重点第 1/2/4 节）和 `docs/rewrite/CONTEXT.md`。前置：T1 已完成，`@inwit/doc-schema` 包可用（`blocksFromPmJSON`/`pmJsonToText`/`thematicBreaksToPageBreaks` 等）。

本任务范围：packages/dto、apps/server 的 DB schema/migration 与**除 digest/selection agent 契约外**的全部 contentMd → contentJson 改造（digest agent 契约是 T3，本任务只保证 server 其余部分编译与测试通过）。**不改 apps/web**（web 会在本任务后暂时编译不过，属预期，T4 修复）。

## 1. DTO（packages/dto/src/document.ts、card.ts、annotation.ts）

- `documentSchema.contentMd: string` → `contentJson`：宽松 PM doc schema，如 `z.looseObject({ type: z.literal('doc') })`（够用即可，不深度校验）。
- `createDocumentInputSchema.contentMd` → `contentJson`（必填，同上 schema）；`updateDocumentInputSchema` 同步（可选字段），refine 里的字段名同步。
- `PDF_PAGE_SEPARATOR` 常量删除，找出所有引用一并处理。
- `titleFromContent(contentMd)` 改为 `titleFromDoc(doc: { contentJson, ... })` 或接收 PM JSON：取首个非空 top-level 块文本（可用 `@inwit/doc-schema` 的 `blocksFromPmJSON`），其余规则（去 `#`、40 字截断、未命名文档）不变。注意 dto 包是否可以依赖 `@inwit/doc-schema`：可以，加 `workspace:*` 依赖。
- `cardSchema.anchorBlock` → `anchorBlockIndex: z.number().int().nullable()`；`createCardInputSchema.anchorBlock` → `anchorBlockIndex: z.number().int().positive().optional()`。
- `pageIndexToAnchorBlock` 删除；`excerptCardInputFromAnnotation` 相应调整（摘录卡片不再塞 anchorBlock；anchorText 仍用 `IMAGE_EXCERPT_QUOTE` 快照）。
- `annotationSchema` 增加 `anchorBlockIndex: z.number().int().nullable()`；`createAnnotationInputSchema`：text 标注允许可选 `anchorBlockIndex`（int positive），pdf/media 不允许（加进各自的 superRefine 规则）。
- `createSelectionCardsInputSchema` 增加 `blockIndex: z.number().int().positive()`（必填）。

## 2. DB（apps/server/src/db/schema.ts）

- `documents`：`contentMd: text('content_md')` → `contentJson: jsonb('content_json')`（PM JSON 类型可用 `unknown`/自定义 `$type`），notNull，默认空 doc `{"type":"doc","content":[{"type":"paragraph"}]}`。
- `cards`：删 `anchorBlock` 列，加 `anchorBlockIndex: integer('anchor_block_index')`。
- `annotations`：加 `anchorBlockIndex: integer('anchor_block_index')`。
- `pnpm -F @inwit/server migrate:generate` 生成 migration，检查生成的 SQL 无误后 `pnpm -F @inwit/server migrate` 执行（远程 dev PG，.env 已配；dev 数据可丢，直接 drop/alter，不写数据迁移）。

## 3. Server 存取链路

- `document.service.ts`：`toPublicDocument`、create/update、`getDocument` 等全部切换到 contentJson。`document-logic.ts` 的 ZWSP/`isBlankDocumentContent` 改为基于 `@inwit/doc-schema` 的 `pmJsonToText` 判空（空 doc/全空白块 = blank）；`shouldEnqueueDigest` 逻辑不变、输入类型改。
- 创建路径：
  - `createDocument`（editor/paste）：入参已是 contentJson，直接存。
  - `createChat`：问题文本构造成 PM JSON 段落存入（不再拼 markdown）。
  - 导入/OCR 完成写库处（找 `import`/`extract`/`ocr` 相关 service/job）：提取出的 markdown → `parseMarkdownToPmJSON`（`@inwit/markdown`）→ `thematicBreaksToPageBreaks` → contentJson。
  - agent 生成文档（weekly_report、对比专题等 `source='agent'` 的创建处）：agent 输出的 markdown 走同一转换管道后写库。
- `retrieval/pipeline.ts`：`IndexableDocument.contentMd` → 存派生文本；`documentEmbeddingText`（`search-logic.ts`）改为从 contentJson 经 `pmJsonToText` 产出；payload/meili 文档里的 `content_md` 键改名 `content_text`。
- `agent/doc-meta.ts`/`doc-meta-logic.ts`：clip/判短的输入改为 `pmJsonToText(contentJson)` 产物。
- 其他引用 `contentMd` 的 server 代码（maps、review、admin 等如有）全部同步。
- server 测试：受影响的纯逻辑测试更新（title、document-logic 判空等）；新增/调整测试覆盖「markdown 导入 → pageBreak 节点编号」的转换函数调用处（转换本身在 doc-schema 已测，这里测接线）。
