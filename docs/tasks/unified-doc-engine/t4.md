## 范围（全部在 apps/web）

### 1. 编辑器/阅读器全 JSON 化（删 markdown 往返）

- `pages/docs/editor.service.ts`：`draftMd`/`lastSavedMd` → `draftJson`/`lastSavedJson`（PM JSON，比较用 `JSON.stringify`）；`hasSubstance`/`isBlankMarkdown`/`EMPTY_DOC_PARAGRAPH` 删除，判空用 `@inwit/doc-schema` 的 `pmJsonToText`；load 用 `doc.contentJson`，save 的 create/update 入参传 `contentJson`。
- `pages/docs/paper-editor.tsx`：删 `contentFromSeed`、`parseMarkdownToPmJSON`/`serializePmJSONToMarkdown` 调用；`content` 直接吃 JSON；`onUpdate` 里 `onChange(editor.getJSON())`。props 的 `seedMarkdown` 改名 `seedDoc`（PM JSON | null）。
- `components/doc/DocView.tsx`：`source` prop 改 PM JSON；删 `contentFromSource`。
- 其他引用 `contentMd` 的前端代码（today、topics、maps、review 等页面/service）全部同步为 contentJson；列表页如只用标题/摘要不展示正文，确认 DTO 字段即可。
- `@inwit/markdown` 从前端依赖中移除（若没有其他使用）。

### 2. 锚定渲染重写（decoration 层）

重写 `pages/docs/anchor-highlight.ts` + `lib/anchors.ts`：

- 数据源改为扫描编辑器 doc 里的实体 mark（用 `@inwit/doc-schema` 的 `findEntityAnchors` 思路，直接在 PM doc 上遍历 mark）。
- **常态高亮**：所有锚范围做并集 → Decoration.inline，统一 class（如 `anchor`）；重叠区只一层底色。卡片锚与标注锚视觉可区分（两个 class），但都走并集。
- **激活高亮**：`activeCardId`/`activeAnnotationId` 变化时，对该 id 的 mark 完整范围（含重叠部分）加激活 class（如 `is-active`）；plugin 存 active id，`updateDecorations` meta 触发刷新（沿用现有 `updateDecorations('anchorHighlight')` 的调用方式）。
- **点击**：hit 区域从 mark 的 data attrs 收集 ids（`data-card-ids` JSON 数组 + `data-annotation-id`），回调 `onAnchorClick(cardIds)` / `onAnnotationClick(ids)`，签名不变。
- `lib/anchors.ts` 的 `AnchorSpec`/`findSubstringRanges`/`groupAnchorsByText` 等全部删除；替换为按 id 索引的轻量结构（`{ id → kind, noteSummary }`，供侧边栏/ tooltip 用）。
- 无锚实体（doc 里扫不到对应 mark）：侧边栏条目显示「原文已删除」置灰态，点击不高亮不跳转（tooltip/文案提示）。
- `ReaderOverlay` 等其他使用 anchors 的组件同步适配。

### 3. 标注新流程（划词 → mark）

- `docs-annotations.service.ts` 的 `addAnnotation`：新增 text 标注时，调用方从编辑器 selection 取 `{ blockIndex, quote, from, to }`（blockIndex = selection 起始所在的 top-level 块 1-based 序号）→ POST 创建（DTO 已支持 `anchorBlockIndex`）→ 成功后对原 `{from,to}` 打 `annotationMark`（用 editor 的 chain：`setMark`/insert mark，或共享包 `applyEntityAnchor` 思路的 editor 命令版）。
- 划词产卡（selection-cards）：同样从 selection 取 `{ text, blockIndex }` 提交（DTO 已改）。
- 手动建卡（`createCard`）如带 `anchorText`，调用方一并给 `anchorBlockIndex`。

### 4. 幂等补打 mark（PLAN 1.5）

- 文档打开（loadDoc）与轮询刷新（refreshDoc/refreshOne）后：对照当前 doc 里已有的实体锚（`findEntityAnchors`）与 `doc.cards`/`annotations` 列表，找出「有 `anchorBlockIndex`+quote 但 doc 里没有 mark」的实体 → 用 `locateQuote` 定位 → 打 mark。
- **编辑器会话**（pane-edit）：打到编辑器 doc 里，随防抖保存落库。**DocView 只读场景**：打在内存 doc（`editor.commands` 但不触发保存——DocView 本就不保存）。
- locate 失败（原文已改）→ 跳过，该实体保持无锚态。

### 5. 一致性兜底

- `paper-editor.tsx` 加 `transformPasted`：剥离粘贴内容里的 `annotationMark`/`cardAnchor`（用 `stripEntityAnchors` 或对 Slice 做 mark 过滤）。
- 保存前（或渲染时）忽略陌生 id 的 mark：decoration 层只对「当前实体列表里存在的 id」上色；陌生 id 的 mark 无样式，编辑器下次保存自然清掉（可加一个保存前的清理命令，简单起见也可以只在渲染层忽略）。

### 6. 清理

- 删除前端所有 markdown parse/serialize 的残余引用、`anchors.ts` 旧 API、`IMAGE_EXCERPT_QUOTE` 在前端锚定逻辑里的特殊分支（摘录卡片本无文字锚，直接走无锚态）。
- CSS：并集底色/激活色/「原文已删除」置灰的样式，参照 `docs/design/v2/inwit.css` 与现有 docs 页样式克制补全。
