### 2. schema 元素（tiptap Extension，schema-only，无 NodeView）

在 `src/schema/` 下：

- `PageBreak` node：name `pageBreak`，group `block`，atom，attrs `{ pageIndex: number（1-based） }`；parseHTML `div[data-page-break]`；renderHTML 输出 `['div', { 'data-page-break': '', 'data-page-index': String(pageIndex) }]`。
- `AnnotationMark`：name `annotationMark`，attrs `{ annotationId: string }`；renderHTML `['span', { 'data-annotation-id': annotationId }]`；parseHTML `span[data-annotation-id]`。
- `CardAnchorMark`：name `cardAnchor`，attrs `{ cardIds: string[] }`；renderHTML `['span', { 'data-card-ids': JSON.stringify(cardIds) }]`；parseHTML `span[data-card-ids]`（解析 JSON 回数组，坏值容错为空数组）。
- `getHeadlessSchema(): Schema`：用 `@tiptap/core` 的 `getSchema()` 构建，扩展集合 = StarterKit（heading levels 1-6、link openOnClick:false/autolink:true、codeBlock 保留默认即可）+ Table/TableRow/TableHeader/TableCell + TaskList + TaskItem(nested) + Image + Subscript + Superscript + PageBreak + AnnotationMark + CardAnchorMark + 一个 schema-only 的 `Video` node（name `video`，block，attrs `{src, mime}`）+ 一个 schema-only 的 `VitalEntity` node（name 对齐 web 现有实现，参考 `apps/web/src/components/doc/extensions.ts` 里的 `VitalEntityNode` 与 `ENTITY_CHIP_TYPE`）。
  - 先读 `apps/web/src/components/doc/extensions.ts`，schema 元素的名字/attrs 必须与 web 编辑器实际使用的一致（这是共享 schema 的意义）。

### 3. 纯函数（`src/` 下，输入输出均为 plain PM JSON object；内部用 `Node.fromJSON(getHeadlessSchema(), doc)` 做位置计算）

- `blocksFromPmJSON(doc)` → `{ index: number; pageIndex: number; text: string }[]`
  - top-level 块，1-based index；`pageBreak` 块 text 为 `''`；pageIndex 从 1 开始，每经过一个 pageBreak 递增；块的 text = 该块内联文本拼接（hardBreak → `\n`，image/video/pageBreak 无文本）。
- `pmJsonToText(doc)` → `string`：块的 text 用 `\n\n` 连接；pageBreak 块输出 `--- 第 ${pageIndex} 页 ---`。
- `locateQuote(doc, blockIndex, quote)` → `{ from: number; to: number } | null`
  - 只在指定 top-level 块内找：先精确 `indexOf`，再空白容错（忽略 `\s+` 后匹配，映射回原位置）。找不到返回 `null`，不做全文降级。from/to 是整个 doc 的绝对 PM 位置。
- `applyEntityAnchor(doc, kind: 'card' | 'annotation', id: string, range: { from: number; to: number })` → 新 doc JSON
  - 用 prosemirror-state 的 Transform `addMark` 实现（headless `EditorState.create` 可用）。
  - kind 为 `card` 时：先把 range 重叠范围内已有 `cardAnchor` mark 的 cardIds 并集合并，再 addMark（`{ cardIds: [...已有, id] }` 去重）；kind 为 `annotation` 时 addMark `{ annotationId: id }`。
- `findEntityAnchors(doc)` → `{ kind: 'card' | 'annotation'; ids: string[]; from: number; to: number }[]`
  - 扫描 doc 里所有 `annotationMark` / `cardAnchor`，输出每个连续 mark 范围。card 的 ids = cardIds 数组，annotation 的 ids = [annotationId]。
- `stripEntityAnchors(doc)` → 新 doc JSON：纯 JSON 遍历，移除所有 `annotationMark`/`cardAnchor` mark（其他 mark 保留）。
- `thematicBreaksToPageBreaks(doc)` → 新 doc JSON：纯 JSON 操作，top-level 的 `{type:'thematicBreak'}` 替换为 `{type:'pageBreak', attrs:{pageIndex: N}}`，N 从 1 按出现顺序递增。

### 4. 测试（vitest，构造 plain JSON fixture，不用 DOM）
