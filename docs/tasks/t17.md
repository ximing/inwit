## 目标
1. **schema**（drizzle 迁移）：
   - 新表 `map_nodes`：id uuid pk, topic_id 外键, parent_id uuid 可空（自引用，三级以内）, title text, status text(uncovered|learning|covered) default 'uncovered', note text?, position int（同级排序）, created_at；索引 (topic_id, parent_id)
   - `cards` 加 map_node_id 可空外键；`documents` 加 map_node_id 可空外键
2. **API**：
   - GET /api/topics/:id/map → 完整树（嵌套 children，每节点带 card_count / doc_count / mastery（该节点卡片平均掌握度：review_states 里 remembered 占比或 ease 归一化，选一个合理定义并说明））
   - POST /api/topics/:id/map/nodes {title, parentId?, note?}（手动加节点）
   - PATCH /api/map-nodes/:id {title?, note?, parentId?, position?}；DELETE /api/map-nodes/:id（节点下的卡/资料 map_node_id 置 NULL，不删内容）
   - PUT /api/cards/:id/map-node {nodeId|null}；PUT /api/documents/:id/map-node {nodeId|null}（手动归位）
   - GET /api/topics/:id/map/summary → {totalNodes, uncoveredNodes, cardCount, masteryPct}（头部进度条用）
3. **状态自动更新**：卡片归属变化或复习反馈后，节点 status 自动重算：无卡=uncovered（除非 Agent 手动标的纯规划节点，见下）；有卡且 mastery<80%=learning；≥80%=covered。注意：Agent 规划的空白节点本来就无卡，uncovered 是正常态；用户手动建的节点同理。
4. dto：MapNode、MapTree、MapSummary

## 验收

- 给某节点卡片刷 remembered 后 status 变化正确
