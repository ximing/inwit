## 目标 1：周报 job（type=weekly_report）
1. 触发：
   - worker 启动时 + 每天凌晨检查：本周还没有该用户的 weekly_report job 就入队（run_at 立即）。简化：worker 里一个 setInterval(1h) 扫 users 表，本周（周一起）无 done/pending 的周报 job 则入队
   - 手动：POST /api/reports/weekly/generate
2. 处理器（pi Agent，工具：read_week_stats / write_document / write_memory）：
   - 统计（SQL 聚合，不消耗 token）：7 天回忆成功率（三档分布）、复习总次数、新卡片数、新建关联边数、各主题地图覆盖率、lapses 最多的 3 个概念（建议重学）
   - Agent 把统计写成一篇**复盘文档**：documents(source=agent, title=「M/D–M/D 学习复盘」)，内容：数据小结 + 自然语言点评（这周哪里稳、哪里在遗忘）+ 建议重学的 3 个概念（每个一句话理由）
   - 复盘文档进文档列表；memories 记一份摘要

## 目标 2：前端
1. **首页提示条**：本周复盘生成后显示「📖 本周复盘已生成：成功率 78%，有 3 个概念在偷偷遗忘。[去看看]」→ 点进复盘文档。复用 T20 提示条样式。GET /api/reports/latest 接口
2. **复盘文档**：正常文档页渲染即可（source=agent 的文档显示一个「AI 复盘」小徽标）
3. **建议重学**：复盘文档里 3 个概念如果对应卡片存在，给出卡片链接（文档内 markdown 链接到 /cards/:id）
4. **复习页完成态**：如果当日刷完且本周有复盘，完成态加一行小字链接「本周复盘 →」
5. 卡片详情页：若该卡有「由原卡拆小」或「拆出子卡」的 related 边，相关卡片区已能显示——确认 reason 可见即可，不用新 UI
