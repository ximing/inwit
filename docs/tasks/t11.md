# T11: 数据模型演进 —— documents + card_links（captures 退役）

工作目录 /Users/ximing/project/mygithub/inwit。先读 docs/prd.md §2.6 和 §5。

## 背景
产品从"聊天流捕捉"演进为"文档为中心"。captures 表由 documents 取代，卡片必须带出处锚点，卡片之间要有关系边。

## 目标
1. **schema 变更**（drizzle 新迁移）：
   - 新表 `documents`：id uuid pk, user_id, thread_id?, title text, content_md text, source text(editor|paste|chat), status text(pending|digested|failed), answer text?, created_at, updated_at；索引 (user_id, created_at desc)
   - 新表 `card_links`：id, user_id, from_card_id, to_card_id, type text(same_concept|confusable|prerequisite|related), origin text(agent|user), created_at；唯一约束 (from_card_id, to_card_id, type)，索引 (user_id)
   - `cards`：加 document_id（原 capture_id 数据迁移后删列）、anchor_text text?（卡片对应的原文片段，逐字引用）、anchor_block text?（段落序号或 id，可空）
2. **数据迁移**（同一个迁移文件里的 SQL 或迁移后脚本，说明选择）：
   - captures → documents：title 取 raw_content 首行/前 40 字，content_md=raw_content，source 映射(text→paste, chat→chat)，status/answer/created_at 直拷
   - cards.capture_id → cards.document_id 按 capture id 对应回填
   - jobs payload 里的 captureId 历史数据不用动（已完成的 job 不再重跑）
3. **代码改造**（全部引用点，无遗漏）：
   - `POST /api/captures` → `POST /api/documents`（{title?, contentMd, threadId?}，title 缺省取首行）；GET 列表/详情/删除同步改名；前端 T13 会对接新 API，本任务先把 server 改完并自测
   - digest agent：`read_capture` → `read_document`；payload {documentId}
   - chat：写 documents(source=chat)，answer 列沿用
   - review/admin/backfill 等所有 join capture 的地方改 join document
   - dto 更新：Document、CardLink、Card 加 anchor 字段；删除 Capture 相关或标记 deprecated
4. **card_links API**：
   - GET /api/cards/:id/links → {outgoing: CardLink+card 摘要[], incoming: 同}
   - DELETE /api/card-links/:id（用户可删 agent 建的边）

## 验收
- migrate 跑通；psql 查 documents 表有原 captures 的全部数据（行数一致），cards.document_id 无 NULL（历史孤儿除外，报告说明）
- smoke：注册/登录 → POST /api/documents → digest 出卡 → GET /api/cards/:id/links 返回结构正确（空数组即可）
- `pnpm -r typecheck && pnpm -r build && pnpm --filter @inwit/server test` 全绿
