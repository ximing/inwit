## 背景与总原则

参考 Vital 的 AI 解析等待态（`~/project/mygithub/vital/apps/web/design/ai-parsing.html` 已评审定稿），把 inwit「文档扔进去」链路的四处提示从"表单 loading"升级为 AI 感交互。**配色为暖调品牌三色：朱红 `--accent` → 金 `--gold` → 墨绿 `--green`，直接引用主题变量，不新增色板**，暗色主题随之自动换亮色调。

核心分层原则（不要混淆）：

- **秒级等待**（capture 提交、文件上传）：完整表演——流光描边壳 + ✦ 呼吸 + shimmer 阶段轮播。
- **分钟级后台 job**（消化中）：克制持续态——行左 2.5px 竖向流光边（`.ai-edge`，4.8s 慢速）+ shimmer 小字，**不轮播、不整壳流光**，用户会离开页面去做别的。
- 上传中的**百分比是真实数据**（分片上传已有 `uploadByDoc[docId].percent`），不是假进度。
- 失败态保持现状的克制红字，不加 AI 皮肤。非 AI 的普通 loading（如「正在加载文档…」）保持现状。

## 目标 1：共享原语——`apps/web/src/ai-flow.css` + 组件

**样式**（新文件，登记进 `style-entry.css`，紧跟 `./styles.css` 之后；它是跨页面共享基础原语，不进任何单一页面目录）：

- 从设计稿 `ingest-ai.html` 的「核心：AI 流光」段原样迁移：`@property --ai-angle`、`ai-flow`、`spark-breathe`、`shimmer-slide`、`stage-in`、`ai-edge-flow` 五个 keyframes/规则；`.ai-shell`（conic-gradient 流光描边壳，padding 1.5px + 内层圆角底）、`.spark`、`.shimmer-text`、`.stage/.out/.in`、`.ai-status`、`.ai-edge`。
- `--ai-a/--ai-b/--ai-c` 三个变量定义放 `apps/web/src/styles.css` 的 `:root`（值即 `var(--accent)` / `var(--gold)` / `var(--green)`，与设计稿一致；暗色主题不用加覆盖，accent/gold/green 本身已按主题切换）。
- `prefers-reduced-motion: reduce` 集中降级块随原语一起放 ai-flow.css（设计稿画板 5 的规则：流光→静态渐变、shimmer→纯文字、✦ 停呼吸、竖边→静态渐变）。

**组件**（新文件 `apps/web/src/components/ai-flow.tsx`，类名/结构与设计稿一致）：

- `AiStageText({ stages, intervalMs = 1300, className }?: { stages: string[] })`：渲染 `<span className="shimmer-text stage">`，按 intervalMs 轮播 `stages`，切换时 `.out` 280ms 后换下一段并加 `.in`（逻辑与设计稿 script 的 wireStage 相同）；`stages.length <= 1` 时静止不轮播；卸载时清理定时器。
- `AiSpark({ delay }?)`：`<span className="spark" style={{ animationDelay }}>✦</span>`。
- 不引入新依赖；纯展示组件，不需要 Service。
