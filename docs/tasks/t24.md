# T24: PDF 原生预览 + 批注 + 扫描版 OCR（融入现有文本系统）

工作目录 /Users/ximing/project/mygithub/inwit。前置阅读：docs/prd.md、apps/server/src/agent/anchors.ts（锚点机制）、apps/server/src/storage/（presign 模式）、apps/web/src/lib/anchors.ts（前端高亮）、docs/tasks/t1.md（导入提取现状）。

## 背景与总原则

现状：导入 PDF 走 `POST /api/documents/import` → unpdf 提取文本存 `contentMd`（页间 `\n\n---\n\n` 拼接）→ **原件丢弃**，阅读页统一 Markdown 渲染。

目标：PDF 保持原生排版预览 + 批注（文本划词 + 框选摘录）+ 扫描版 OCR 提取。**核心原则：一份文档、两种视图，不搞两套系统**——

- `contentMd` 仍是唯一真相：digest 切卡、检索索引、卡片锚点（anchorText/anchorBlock）、批注 quote 全部锚在它上面，AI 管线零改动；
- PDF 原件是同一条 `documents` 记录上的「展示附件」（S3），只有阅读视图按 `fileMime` 切换渲染器；
- 批注复用现有 `annotations` 表扩展列，不建新表；批注数据存**自有归一化格式**（不存 viewer 库原生格式，为 EmbedPDF v2→v3 升级留隔离层）；
- 页 ↔ block 映射：PDF 提取按 `\n\n---\n\n` 分页拼进 contentMd，`anchorBlock` 即块索引（已入库，前端目前未消费），PDF 视图据此跳页，再用 quote 在页内文本层搜索精确定位。

技术选型：EmbedPDF **v2.15.0（pin 精确版本，不上 v3-next）**，headless 插件模式（`@embedpdf/core/react` + plugin-annotation / plugin-selection / plugin-capture），UI 全部自绘。依据：MIT、PDFium WASM 渲染保真、批注可 import/export JSON、v3 官方声明不建议生产且 capture 插件尚未移植。

## 目标 1：数据模型（一次 migration，全可空、向后兼容）

`documents` 表增加：

```
file_key    text        null   -- S3 对象 key（原件），DB 只存 key 不存 URL
file_mime   varchar(64) null   -- 'application/pdf' 等
file_size   integer     null
page_count  integer     null
```

`annotations` 表增加：

```
kind        varchar(16) not null default 'text'  -- 'text' | 'pdf'（'media' 预留）
page_index  integer     null                     -- PDF 页码（0-based）
geometry    jsonb        null                    -- { quads: number[][], color?: string }，PDF 用户坐标系
image_key   text         null                    -- 框选摘录截图 → S3 key
position_ms integer      null                    -- 影音时间点（本任务不做 UI，仅预留）
```

`cards` 表增加：

```
image_key   text        null   -- 摘录截图 → S3 key（卡片渲染图片，扫描版框选转卡的必备）
```

DTO 同步（packages/dto）：
- `documentSchema` 加 `fileMime`/`pageCount`（**fileKey/imageKey 一律不下发**，前端永远不碰 key，图片经服务端签发 URL）；
- `annotationSchema` / `createAnnotationInputSchema` 加批注相关可选字段，create 时按 kind 校验组合：`pdf` 必须有 `pageIndex + geometry`，`text` 不许带这些字段；
- `cardSchema` 加 `hasImage: boolean`（由 imageKey 派生，图片内容走签发接口）。

另外 `createDocumentInputSchema` / `contentMd` 的空值策略：扫描版放行空 contentMd（`createDocument` service 层对 `source='import'` 允许空串，digest 在 contentMd 为空时不自动入队）。**contentMd 的 100k 上限仅存在于 DTO（编辑器/粘贴入口），import/ocr 走 service 直写不受其约束**；长文档（数百页 OCR 结果）的 digest 分块由 digest agent 既有逻辑处理，实现时验证并在报告记录。

## 目标 2：导入改造——S3 分片直传，取消大小上限（全局改动）

现状 `/api/documents/import` 是 multipart 经服务端中转（`part.toBuffer()` 全量进内存，上限 20MB）。改为 **S3 multipart 分片直传**（每片 5MB，S3 分片下限即 5MB），**全局取消导入大小上限**（仅保留防滥用的技术天花板 2GB，走 server config）：

1. **上传三步走**（新接口，全部属主隔离 + key 白名单校验，参照 `storage/presign-logic.ts` 头像模式）：
   - `POST /api/documents/import/init`（body：filename/mime/size/topicId?）→ 建 documents 行（status=pending，fileKey=`docs/{userId}/{docId}/source.{ext}` 先占位）→ S3 CreateMultipartUpload → 返回 `{ documentId, uploadId, key }`；
   - `POST /api/documents/import/:id/parts`（body：partNumbers 批量）→ 返回各分片的 presigned UploadPart URL（TTL 15min，前端按 5MB 切片直传 S3，收集 ETag；失败分片前端重试）；
   - `POST /api/documents/import/:id/complete`（body：`{ uploadId, parts: [{partNumber, etag}] }`）→ CompleteMultipartUpload → 更新 fileSize → **入队 `extract` job（见目标 3）立即返回**，不阻塞；
   - 中断恢复：前端 localStorage 记录 `{documentId, uploadId, 已完成分片}`，刷新后可续传；另提供 `POST /api/documents/import/:id/abort` 清理（worker 定期清扫超时未完成的 multipart，防存储泄漏）。
2. **文本提取改异步**：原同步的 `extractImportedMarkdown` 不再在请求里跑，移入 worker 的 `extract` job（目标 3）。服务端/ worker 处理大文件时**落临时文件再处理，不全量进内存**。
3. 新增接口：`GET /api/documents/:id/file` → 属主校验 → `presignGet(fileKey)` → 返回 `{ url, mime }`（TTL 1h）。遵守规范：客户端只拿带过期时间的 URL。
4. 删除文档时级联删 S3 对象（含 excerpts 前缀下所有对象，best-effort，失败记日志不阻塞）。

## 目标 3：提取/OCR 异步管线（qwen-vl-ocr，独立 BYOK 配置）

**全程异步**：import complete 只入队 job 就返回，用户立刻能在 PDF 视图看原件；文本提取与 OCR 都在 worker 后台跑。

1. **两个新 job 类型**（`src/jobs/`、`src/agent/` 按既有模式分发）：
   - `extract`（payload `{ documentId }`）：S3 GetObject → 落临时文件 → `extractImportedMarkdown`（现有逻辑，unpdf 按 `\n\n---\n\n` 分页）→ 写回 contentMd/pageCount。**文本非空** → 链式入队 `digest`；**文本为空（扫描版）** → 链式入队 `ocr`；
   - `ocr`（payload `{ documentId, totalPages, donePages, failedPages }`）：S3 原件 → 按页栅格化 PNG → 逐页调百炼 OCR → 按 `\n\n---\n\n` 分页拼接写回 contentMd → 链式入队 `digest`。处理中持续更新 donePages（前端显示「识别中 12/48 页」）；
   - 失败重试沿用 jobs 表 attempts/lastError + `recoverStuckJobs`；**粒度到页**：job payload 记录已完成页，重试只补失败页，不整本重跑。
2. **超长文档：split 分割批处理，不拒绝、必须 OCR 完**：
   - 无页数上限。按批处理：每批 N 页（默认 10，server config 可调），批间更新进度、批内并发 ≤2 控制 QPS；单批失败只重试该批；
   - 数百页文档的耗时以 10 分钟计，进度条 + 可断点续跑是必须品（jobs 表 recoverStuckJobs 超时回收后要能从 donePages 继续）；
   - backlog：后续可切阿里云 Batch API 进一步降成本（非实时场景天然契合）。
3. **OCR 调用方式**（依据阿里云官方文档 https://help.aliyun.com/zh/model-studio/qwen-vl-ocr）：
   - 模型 `qwen-vl-ocr`（稳定版，默认）/ `qwen-vl-ocr-latest`，模型名走配置。**不用 qwen3.5-ocr（贵）**；
   - ⚠️ qwen-vl-ocr 全系（含 2025-11-20）**不支持 PDF 直传**（PDF 直传是 qwen3.5-ocr + Response API 的专属能力），必须走 **Chat API + 服务端拆页为图片** 的路径；
   - 拆页：`pdfjs-dist` legacy build + `@napi-rs/canvas` 服务端栅格化，150–200 DPI PNG（小字不清可调高，token 消耗随分辨率增长，用 `max_pixels` 默认值兜底）；注意与前端的 EmbedPDF PDFium 是两套渲染，互不影响（OCR 只需要位图）；
   - 请求：**每页一个请求**（qwen-vl-ocr 的 max_tokens 默认 4096，密排页面多页合并易截断；单页请求同时带来天然的页级进度与页级重试），图片以 base64 data URL 内联（`image_url`）；
   - 任务参数参照文档「调用内置任务」与 API 参考，选文字识别/文档解析内置任务；图像倾斜在 DashScope 参数里开 `enable_rotate`；
   - 计费为 token 制（输入=图像 token + 输出 token）；北京地域开通后 90 天内有 100 万 token 免费额度。
4. **BYOK：OCR 独立配置**（不复用 llm_configs 的 dashscope 条目）：
   - 新表 `ocr_configs`：`userId`（unique）、`apiKeyEncrypted`、`model`（默认 `qwen-vl-ocr`）、`baseUrl`（可空，默认百炼兼容端点）；加解密复用 `src/llm/crypto.ts`；
   - 接口：`GET/PUT /api/ocr-config`、`POST /api/ocr-config/test`（发一张小图验证，错误信息做 key 脱敏，照抄 testLlmConfig 的 redact 模式）；
   - 解析顺序：用户 OCR 配置 → 系统 `config.DASHSCOPE_API_KEY` 兜底；
   - 设置页新增独立「文档解析（OCR）」区块：key、模型名（默认 qwen-vl-ocr）、测试按钮，文案说明用途与计费归属（走用户自己的百炼账户）。
5. **进度可见 + 可重试**（文档内，不建任务中心）：
   - 文档列表行/详情页复用现有 job 轮询（docs.service 的 syncPolling 模式）展示阶段进度：「上传中 x%（分片直传，前端本地进度）→ 提取中… → 识别中 12/48 页 → 消化中… → 完成」；
   - 失败态：文档标记 `failed` + 透出 lastError（key 无效/超时/栅格化失败），文档行显示**「重试」按钮** → `POST /api/documents/:id/retry`（按当前阶段重新入队 extract/ocr/digest，ocr 跳过已完成页）。

## 目标 4：前端 PDF 阅读视图（EmbedPDF headless）

1. 阅读页分派：`doc.fileMime === 'application/pdf'` → 新组件 `<PdfPane>`，否则现有 `<PaneRead>`（不动）。EmbedPDF 路由级懒加载（WASM 体积），加载态文案克制。
2. 新增 `apps/web/src/pages/docs/pdf-pane.service.ts`（Service 子类，参照 today.service.ts 模式），组件 `observer` + `useService`，不引入新状态管理。
3. PdfPane 能力：
   - 加载：`GET /api/documents/:id/file` → presigned URL 喂 EmbedPDF loader；
   - **批注重绘**：`kind='pdf'` 的 annotations → 适配函数 → `importAnnotations`；适配层集中在一个文件 `pdf-pane/annotation-adapter.ts`（自有 schema ⇄ EmbedPDF AnnotationTransferItem 双向转换）；
   - **划词**：selection plugin `onSelectionChange` → 浮出现有同款工具条（「记一笔 / 转为卡片」）→ 现有 `createAnnotation`（带 pageIndex+geometry+quote）/ `enqueueSelectionCards`；

4. **导入 UI 改造**（配合目标 2 的全局改动）：docs.service 的 `importFile` 去掉 20MB 前端校验，改为分片上传器（5MB 切片、并发 ≤3、分片失败重试、总体进度条、localStorage 断点续传）；导入按钮与拖拽入口不变。小文件（<5MB，txt/md/docx/epub）走同一条分片链路（单片即完），不保留旧 multipart 路径——全局限一，不留两套。
4. 批注列表侧栏、CardRail 复用现有组件（只认 DTO 不认渲染器）。

## 目标 5：批注 ⇄ 卡片闭环 + 出处跳转

1. **批注/卡片 → PDF 定位**：点击批注或卡片 → `anchorBlock`（或 annotation.pageIndex）按页分隔符换算页码 → 跳页 → quote 在该页 PDF 文本层搜索 → 高亮闪烁（对齐现有 `applyUrlAnchor` + 滚动闪烁体验）；`docAnchorPath` URL 参数机制平移到 PDF 视图。
2. **PDF 划词 → 卡片**：走现有 `POST /api/documents/:id/selection-cards`，job 完成卡片入库后 `anchorBlock` 由服务端 `resolveAnchor` 照常计算（quote 在 contentMd 里能匹配——OCR 文本与 PDF 文本层同源，匹配率有保障；匹配不上时退化页级定位）。
3. **顺手补缺**：复习页/主题页卡片加出处跳转（`cardPath` 改指 `docAnchorPath`），文本/PDF 文档通吃。

## 目标 6：框选摘录 + 卡片图片渲染（MarginNote 式摘录）

1. capture plugin 框选 → 截图 Blob → 上传：新增 `POST /api/documents/:id/excerpts` → 校验（png/jpeg/webp ≤5MB，照抄头像 presign-logic 模式）→ presign PUT → 前端直传 S3，key `docs/{userId}/{docId}/excerpts/{annotationId}.png`（截图很小，不需要分片）；
2. `createAnnotation({ kind:'pdf', pageIndex, geometry, imageKey, note? })`；批注列表里显示截图缩略图——新增 `GET /api/annotations/:id/image` 服务端签发 presigned URL（**标注上必须能看到框选截图**）；
3. 截图批注「转为卡片」：**卡片要支持渲染图片**——
   - `cards` 表新增 `image_key`（见目标 1），转卡时把批注的 imageKey 带上，卡片 example 存 OCR/手动补充的文本（可为空）、anchorText 存 `[图片摘录]` 占位 + anchorBlock 存页码；
   - 新增 `GET /api/cards/:id/image` 签发 URL；复习页、文档页 CardRail、卡片详情的渲染组件统一支持：有 imageKey 的卡片在正面显示截图（复习体验 = 看着截图回忆概念）；
   - digest agent 不消费 image_key（文本管线不动），图片卡只来自用户手动框选转卡。

## 验收

- P1（目标 1–2）：老文档行为不变；50MB+ PDF 分片直传成功（断网续传可恢复）；小文件走同一链路；`/file` 签发 URL 可用；migration 可重复执行；

## 已确认的决策（不再搁置）

1. OCR key **独立配置**（新表 `ocr_configs` + 设置页独立区块，不复用 llm_configs）；
2. 模型 **qwen-vl-ocr**（成本原因弃 qwen3.5-ocr，走服务端拆页 + Chat API）；
3. 超长文档 **split 分割批处理，必须 OCR 完**，无页数上限；
4. 导入**取消大小上限**，全局改 S3 分片直传（5MB/片），不留旧 multipart 路径；
5. **卡片支持渲染图片**（cards.image_key + 签发接口，复习页可见框选截图）；
6. 进度展示在**文档行内**，必须带阶段进度与重试能力。
