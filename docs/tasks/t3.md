## 目标
1. **认证**（照搬 vital auth 模式，可简化）：
   - POST /api/auth/register（email+password，argon2 哈希）
   - POST /api/auth/login → JWT access token（httpOnly cookie）+ refresh token（落库或简化版：长 TTL cookie，选一个并说明）
   - POST /api/auth/logout、GET /api/auth/me
   - fastify 装饰器 authenticate，后续所有业务路由挂它
2. **BYOK LLM 配置**：
   - GET/POST/PUT/DELETE /api/llm-configs，支持 provider: openai | deepseek | claude | zhipu | dashscope
   - api_key 落库前用 LLM_KEY_ENCRYPTION_KEY（env，32字节hex）做 AES-256-GCM 加密（参考 vital llm/crypto.ts），接口返回值永远不回显完整 key（只返回前 6 位 + ****）
   - 设默认模型接口：PUT /api/llm-configs/:id/default
   - POST /api/llm-configs/:id/test：用该配置真实调一次模型（"ping" 级别请求），返回 ok/fail+错误信息
3. **模型解析层** src/llm/pi.ts：用 @earendil-works/pi-ai（先 `pnpm --filter @inwit/server add @earendil-works/pi-ai @earendil-works/pi-agent-core`，版本对齐 vital 的 0.85.1），实现 resolveModelFor(userId)：读用户默认 llm_config → 解密 → 返回 pi-ai 可用的 model/provider 配置；未配置时回落到系统 DashScope（DASHSCOPE_API_KEY，OpenAI 兼容模式 https://dashscope.aliyuncs.com/compatible-mode/v1，模型 qwen-plus）。
   - pi-ai 对各 provider 的接入方式读 node_modules/@earendil-works/pi-ai 的类型/文档或 vital 的用法。
4. **用量记录**：src/llm/usage.ts，封装调用，每次成功/失败都写 llm_usage_logs（capability=chat）。
