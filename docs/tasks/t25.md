## 背景与总原则

批注（annotations 表，quote+note，kind=text/pdf/media）是用户阅读时亲手标记的重点，但目前只存在于文档页内部：全局搜索搜不到、没有 deep link、agent 看不到。本任务做三层召回的**第一层「被找到」**：批注进检索层（Qdrant 向量 + Meili 稀疏混合召回），搜索结果新增「批注」组，点击 deep link 落回文档页对应批注并闪烁定位。

核心原则：

- **批注是原材料，卡片是成品**：批注保持轻（不进 SM-2 复习队列、不建平行体系），只补齐「可被找到」的基础设施；
- **复用现有检索原语**：不新造管线，`upsertBoth`/`deleteBoth`/`hybridSearchIds`/`withSearchFallback` 直接复用，批注只是第三类实体；
- **note 为主、quote 为辅**：note 是用户自己的思考，embedding 以它为主；`[图片摘录]` 占位符一律归一为空，不污染向量空间；
- **索引失败不阻塞写路径**：warn-only fire-and-log（仿 `tryIndexDocument`），不回滚批注写入；
- 顺带修复两个历史缺口：纯文字批注无法转卡片（`excerptCardInputFromAnnotation` 只对截图批注生效）、手工建卡不进索引（`createCard` 无索引调用，转卡产的卡搜不到会让第一层目标落空）。

## 目标 1：检索管线支持批注实体（apps/server/src/retrieval/）

pipeline.ts 新增（全部同文件，私有原语可见）：

- `IndexableAnnotation`：`{ id, userId, documentId, kind, quote, note }`。
- `annotationEmbeddingText(a)`：note trim 为主 + quote 截断 300 字符为辅，`\n` 连接；`quote === IMAGE_EXCERPT_QUOTE` 归一为空。返回空串表示「无语义内容」。
- `indexAnnotation(a)`：先 `ensureRetrievalStores()`；payload/meiliDoc 约定 `{ id, annotation_id, user_id, doc_id, kind, note(clip 500), quote(clip 300), text }`；**text 为空时只进 Meili 不进 Qdrant**（直接编排 `qdrant.deletePoints(...).catch(() => {})` + `meili.upsertDocuments`，绕过 vector 必填的 upsertBoth——纯截图未写笔记的批注零 embedding 成本）；否则 embed → `upsertBoth`。
- `deleteAnnotationFromIndex(id)` / `tryIndexAnnotation` / `tryDeleteAnnotationFromIndex`（warn-only 包装，仿 pipeline.ts:217-238 的 tryIndexDocument 模式）。
- `searchAnnotations(userId, query, limit=8, options?)`：包 `hybridSearchIds`，自定义 `annotationIdOf`（payload.annotation_id ?? String(id)）与 `annotationPayloadText`（payload.text ?? note+quote 兜底）。
- 顺带新增 `tryIndexCard`（warn-only 包装 `indexCard`），供目标 5 手工建卡使用。

registry.ts：`annotationsStoreName()` → `inwit_annotations_dev/prod`（按 NODE_ENV 后缀，照 cardsStoreName）；`ensureRetrievalStores` 加第三对 ensure：`qdrant.ensureCollection(name, { payloadFields: ['user_id', 'annotation_id', 'doc_id'] })` + `meili.ensureIndex(name, ANNOTATION_INDEX_SETTINGS)`。

meili.ts：`ANNOTATION_INDEX_SETTINGS`——filterableAttributes `['user_id','annotation_id','doc_id','kind','id']`，searchableAttributes `['note','quote','text']`，localizedAttributes cmn（照 CARD_INDEX_SETTINGS 模式）。

self-test.ts：照卡片段加批注段——建批注 → indexAnnotation → searchAnnotations 命中 → deleteAnnotationFromIndex → 不再命中；另加 Meili-only 分支用例（note 空 + quote 为占位符：不进 Qdrant、quote 关键词经 Meili 可命中）。

## 目标 2：索引 hook 与存量回填

- `annotations/annotation.service.ts`（service 层 hook，web/mobile 同生效）：`createAnnotation` 的 returning() 之后、`updateAnnotation` return 前调 `tryIndexAnnotation(row)`；`deleteAnnotation` 删除后调 `tryDeleteAnnotationFromIndex(id)`。

## 目标 3：搜索「批注」组（DTO → server → web）

DTO（packages/dto/src/search.ts）：

```ts
searchAnnotationSchema = { id, documentId, documentTitle: string|null, kind, quote(服务端截断~140), note(截断~200), pageIndex: number|null, createdAt }
searchResultSchema = { documents, cards, annotations: searchAnnotationSchema[] }
```

server search/search.service.ts：

- `searchAnnotationIdsIlike`：`or(ilike(note, p), ilike(quote, p))`，按 updatedAt desc；
- `loadAnnotationsByIds`：annotations leftJoin documents 取标题（docDisplayTitle 合成 documentTitle），clipChars 截断，orderByIds 保序；
- `idsInTopic` 扩 annotations 分支：`annotations join documents on documentId where documents.topicId = ?`（topicId 过滤只靠 filterIds DB 复核，payload 不冗余 topic_id——文档换主题后 payload 不过期）；
- `search()` 三路 Promise.all 并行，scoped 时同样 fallbackIfEmpty。

web：

- `routes.ts`：`docsPath` opts 加 `annotation?: string`；新增 `docAnnotationPath(docId, annotationId)`（序列化为 `/docs?doc=X&annotation=Y`）。
- `docs.service.ts`：新增 `applyUrlAnnotation(id)`——`this.annotations` 里命中才生效，置 `appliedUrlAnchor` 后调已有 `openAnnotation(id)`（activeAnnotationId/scrollAnnotationId/cardRailOverlayOpen 全套状态已具备）；`loadDoc` 签名扩第三参；docs/index.tsx 读取 searchParams 的 `annotation` 传入。已有滚动+闪烁 effect（index.tsx `.note-item[data-annotation-id]` + scrollFlashAnnotationAnchor）自动生效，零新增。
